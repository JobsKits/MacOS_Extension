## JobsFlutterRunner：修复内置 iOS 模拟器初始化被询问两次

来源：用户新电脑（`flutter@aito_ie`）右键"运行 Flutter 项目" → 选 iOS 模拟器入口 → 本机无模拟器 → 机型 / 系统各被询问两轮。

### 根因

`choose_device` 的 `while true` 循环中 `ios) select_ios_simulator && return ;;` 只在成功时退出。
`create_simulator` 一旦创建失败就 `return 1`，控制权回到设备列表；用户再次选择 iOS 入口即进入第二轮询问。
而 `types` / `runtimes` 返回的都是未排序全量清单，编号 / fzf 回车首项正好是
iPhone 18 Pro / iOS 27.1 —— 记忆第十三节已确认该组合返回 403 / `Incompatible device`，所以第一次必然失败。

### 修复内容

- `Scripts/FlutterRunner.jxa`
  - 抽出 `iphoneTypes(data)`，`deviceTypes(path)` 原行为不变（保持 1 参数调用兼容）。
  - 新增 `preferred-types <list.json> [arch]`：型号完整保留，按「已确认支持 > 未知 > 明确不支持」排序，
    同档保持 Xcode 原顺序；无可搭配系统的型号追加「（本机无可搭配系统）」标注。
  - 新增 `compatible-runtimes <list.json> <arch> <deviceTypeID>`：排除明确不支持的系统，
    已确认支持的排前、组内版本新的优先；非确认支持的追加「（未确认支持）」标注。
  - 兼容判定 `compatibility()`：优先用 runtime 的有效 `supportedDeviceTypes` 白名单，
    缺失 / 空 / 不完整名单不猜测为不支持，退回 device 的 `min/maxRuntimeVersion`（数值或字符串）。
  - 新增 `iosRuntimesForArchitecture()`，按当前架构过滤 runtime，字段缺失不据此排除。

- `Scripts/RunFlutterProject.zsh`
  - `create_simulator` 改为内部循环的两段式：先选型号，再只列匹配该型号的系统。
  - 新增 `confirm_simulator_reselection()`：只有明确不兼容且精确输入 `r` / `R` 才重选，
    回车、其它输入、EOF 一律停止并说明。
  - 创建失败区分：仅 Xcode 明确写出 `Incompatible device` 才走重选门禁；
    超时（124）与泛化 `Unable to create a device for device type` 等一律停止，不自动重试。

- 文档：`README.md` 与 `Scripts/README.md` 增量同步交互口径与 2026-10-21 修复记录。

## JobsFlutterRunner：修复 Xcode 27 打开模拟器界面失败（Unable to find application named 'Simulator'）

来源：用户新电脑（Xcode 27.1）右键运行，模拟器创建 + boot + bootstatus 全部成功，随后
`/usr/bin/open -a Simulator --args -CurrentDeviceUDID <UDID>` 报
`Unable to find application named 'Simulator'` 并 `die` 终止整个流程。

### 根因

Xcode 26 / 27 把模拟器界面改名为 `DeviceHub.app`，位置从
`Xcode.app/Contents/Developer/Applications/` 移到 `Xcode.app/Contents/Applications/`；
本机 `Contents/Developer/Applications` 目录已不存在。按名字 `Simulator` 打开必然失败。
规范源 `【MacOS】📱双击初始化iOS模拟器.command` 的 `sim_check_environment()` 用
`xcrun --find simctl` 反推 Developer 目录并按三个候选路径查找，本机命中第三个候选。

### 改动

- `Scripts/RunFlutterProject.zsh`
  - 新增 `simulator_interface_path()`：候选依次为 `<developer>/Applications/Simulator.app`、
    `<developer:h>/Applications/Simulator.app`、`<developer:h>/Applications/DeviceHub.app`。
  - 新增 `simulator_interface_app()`：`xcrun --find simctl` 反推 Developer 目录后调用前者。
  - 新增 `reveal_simulator_interface()`：`Simulator.app` 带 `-CurrentDeviceUDID`，`DeviceHub` 只打开并提示按名选中；
    找不到或打不开只记日志返回 1。
  - 原 `open -a Simulator ... || die` 改为调用该函数，失败只提示，不终止运行。
- 测试：Shell 新增 5 项（Xcode 27 DeviceHub 布局、旧版 Simulator 布局、无任何界面返回 1、
  缺失只警告、打开失败只警告）。
- 文档：`README.md` 表格行、常见问题新增两条、新增修复记录段，验证数字改为 27 项 / 123 断言。

## JobsFlutterRunner：FVM SDK 未就绪时自动补齐

来源：用户换机后右键运行报「项目声明了 FVM，但本地 .fvm/flutter_sdk 尚未就绪」，要求直接装上。
实际是 `.fvm/flutter_sdk` 仍指向旧机器 `/Users/jobs/fvm/versions/3.47.7`（断链），
而本机 `~/fvm/versions/3.47.7` 已经存在——不需要下载，只需重建链接。

### 改动

- `Scripts/FlutterRunner.jxa`：新增 `fvm-version` 模式，读 `.fvmrc` 的 `flutter`
  或 `.fvm/fvm_config.json` 的 `flutterSdkVersion`；非字符串、空值、
  含危险字符（正则白名单 `^[0-9A-Za-z][0-9A-Za-z._+\-/:@]{0,63}$`）一律报错，防止参数注入。
- `Scripts/RunFlutterProject.zsh`
  - 新增 `project_fvm_config()` / `resolve_fvm_cli()`（支持 `JOBS_FVM_BIN` 覆盖）。
  - 新增 `prepare_project_fvm_sdk()`：SDK 就绪直接返回；否则读声明版本 → 回车确认 →
    缓存缺失才 `fvm install`（1800 秒）→ `fvm use --skip-pub-get --skip-setup` →
    **若 use 只写配置没建链接，按本机缓存兜底 `ln -s`** → 校验 `bin/flutter` 可执行。
  - `find_flutter` 由直接 die 改为调用补齐，失败才 die。
  - 自述第 4 条改为"项目声明的 FVM SDK 缺失时会确认后下载"。
- 测试：Shell 新增 7 项、JSON 新增 2 项。

### 关键坑

- macOS **没有 `/bin/true`**（只有 `/usr/bin/true`），测试 stub 用错路径会让 `-x` 判定为假。
- `fvm use` 在 `.fvmrc` 版本已一致时只写配置、不重建 `.fvm/flutter_sdk`，必须兜底建链。
- 预先 `rm` 断链反而会让 fvm 跳过建链，改为交给 fvm 处理再兜底。
- fvm 需要项目有 `pubspec.yaml`，否则不建链接（临时验证目录要补 pubspec）。

### 验证

  → `已按本机 FVM 缓存重建` → `-> /Users/wx996768/fvm/versions/3.47.7`，SDK_OK。
- Shell 39 项 / 192 断言、JSON 28 项 / 323 断言、Swift 原生回归、安装器 19 项 / 108 断言通过；

## 用户项目 iOS 构建失败：部署目标 13.0（非本扩展缺陷）

现象：`JobsBaseConfig@JobsFlutterBaseConfigDemo` 右键运行一路跑通（FVM 补齐、设备选择、
后台 launchd 运行），最后 Xcode 构建报
`Target Integrity: IPHONEOS_DEPLOYMENT_TARGET is set to 13.0, but the range ... is 15.0 to 27.1.x`，
指向 `ios/Pods/Pods.xcodeproj`。

根因：`ios/Podfile` 第 54 行有 `platform :ios, '15.0'`，但第 99 行 `post_install` 又把
所有 pod target 的 `IPHONEOS_DEPLOYMENT_TARGET` 强制写成 `'13.0'`，`pod install` 生成的
`Pods.xcodeproj` 因此是 13.0；Xcode 27 最低要求 15.0。Runner.xcodeproj 侧已被 Flutter 升到 15.0。

处理（经用户确认）：备份 `ios/Podfile` → `ios/Podfile.bak-20261021-1425`，
99 行 13.0 → 15.0，`cd ios && pod install` 重建 Pods；复核 `Pods.xcodeproj` 36 处全部为 15.0。
pod install 的 base configuration 警告在 Flutter 项目可忽略。
`JobsFlutterRunner/README.md` 常见问题新增该条诊断与修复步骤。

经验：Flutter 3.47 会自动升级 Runner 的 pbxproj / AppFrameworkInfo.plist / Podfile 的 platform，
但**不会改 post_install 里手写的 deployment target**，换 Xcode 大版本时要单独查这一处。
